# Resonator Filter - Design Document

## 1. Purpose

The Resonator Filter is a Supabase Edge Function designed to analyze and potentially modify text to ensure it aligns with Raizin Vault's core frequencies (values, tone). It acts as a quality control and harmonization layer for communications generated by agents or other system components.

## 2. Function Name

`resonator_filter`

## 3. Inputs

The function will accept a JSON object with the following properties:

```json
{
  "text_content": "string", // The text to be analyzed/filtered.
  "target_frequency_profile": { // Optional: Specifies desired characteristics
    "core_values_emphasis": ["trust", "innovation"], // Example: which core values to emphasize
    "desired_sentiment": "neutral" // "positive", "neutral", "negative" (guidance)
  },
  "source_agent_id": "string (optional)" // ID of the agent that generated the text
}
```

## 4. Outputs

The function will return a JSON object:

```json
{
  "filtered_text": "string",     // The original or modified text.
  "alignment_score": "float",    // Overall alignment (0.0 - 1.0). 1.0 is perfect alignment.
  "sentiment_score": "float",    // Detected sentiment (-1.0 (neg) to 1.0 (pos)).
  "value_alignment": {         // Alignment with each core value
    "trust": "float",
    "innovation": "float",
    "sovereignty": "float"
    // ... other values if defined
  },
  "applied_modifications": ["string"], // List of modifications made (e.g., "removed_negative_phrase", "toned_down_hype")
  "warnings": ["string"]           // Any warnings (e.g., "strong_negative_sentiment_detected")
}
```

## 5. Core Logic (Initial Implementation)

### 5.1. Value Alignment:
*   Load core values from `values.json` (similar to how Clarity Agent did, perhaps via hardcoding for prototype or env vars for the function).
    *   **Trust:** Check for words/phrases that undermine trust (e.g., "guaranteed," "always," "never" without qualification, overly complex jargon without explanation). Penalize score if found.
    *   **Innovation:** Check for phrases that encourage new ideas vs. dismissive language. (This is harder with rule-based, might be a placeholder).
    *   **Sovereignty:** Check for overly authoritative or demanding language vs. empowering language.
*   *Scoring:* Each value alignment starts at 1.0. Deduct points for violations.

### 5.2. Sentiment Analysis (Simple Keyword-Based):
*   Maintain lists of positive and negative keywords.
*   Count occurrences of positive/negative keywords in `text_content`.
*   Calculate `sentiment_score` based on the ratio (e.g., `(pos_count - neg_count) / total_words`).
*   If `target_frequency_profile.desired_sentiment` is provided, check if detected sentiment deviates significantly. If so, add a warning.

### 5.3. Text Modification (Minimal for Initial Version):
*   **Extreme Negativity:** If very strong negative keywords are found and `desired_sentiment` is not 'negative', the filter might:
    *   Attempt to replace the keyword with a milder synonym (very basic, hardcoded map).
    *   Or, more safely, just flag it heavily in `warnings` and reduce `alignment_score`.
    *   For the first version, flagging and scoring will be prioritized over risky auto-modification.

### 5.4. Overall Alignment Score:
*   Calculated as a weighted average of value alignment scores and sentiment alignment (how close detected sentiment is to desired, or to neutral if none desired).

## 6. Data Sources for Logic:
*   `values.json`: For core value definitions (content will be hardcoded into the function for v1 of filter).
*   Internal keyword lists for sentiment (positive/negative words).

## 7. Future Enhancements:
*   Use pre-trained NLP models for more nuanced sentiment and value alignment.
*   More sophisticated text modification capabilities (style transfer, summarization).
*   Learning from feedback (if a response was downvoted, analyze its filter scores).
*   Allowing `target_frequency_profile` to specify more granular tone dimensions (clarity, empathy, etc.).
